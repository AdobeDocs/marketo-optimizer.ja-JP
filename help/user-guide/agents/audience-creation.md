# プログラム用オーディエンスの作成

[!DNL Adobe Marketo Optimizer]では、[_ユーザーリスト_](../audiences/people-lists.md)&#x200B;がユーザージャーニーのオーディエンスを定義します。これは、自動的に更新される動的フィルターベースのリストか、固定メンバーシップを持つ静的リストのいずれかです。 [ チャットインターフェイス ](./chat-interface.md)から、_オーディエンス作成_ [ スキル ](./skills.md)が、ガイド付きの会話を通じてユーザーリストを作成、適応、編集します。

* **スキル** - `audience-creation`および`people-list-comparison`
* **Invocation** - オーディエンス条件を直接記述するか、[!DNL Marketo Engage] スマートリストをアップロードするか、編集する既存のリストに名前を付けます
* **スマートリストの適応時に[!DNL Marketo Engage]を読み取る/**&#x200B;に書き込む – [!DNL Marketo Optimizer]

## サポートされているワークフロー {#workflows}

Coworkerは3つのオーディエンス作成ワークフローをサポートしており、どのワークフローがリクエストに適用されるかを判断します。 意図があいまいな場合は、先に進む前に尋ねられます。

| ワークフロー | 利用するタイミング | プロンプトの例 |
|---|---|---|
| **ゼロから作成** | 基準またはメンバーシップで定義された新しい人物リストが必要です。 | _「北米のSaaS企業のマーケティング担当バイスプレジデントの動的リストを作成します。」_ |
| **[!DNL Marketo Engage] スマートリストを適応** | 既存の[!DNL Marketo Engage] スマートリストまたはスマートキャンペーンがあり、同等の人物リストが必要です。 | _「このMarketo スマートリストをユーザーリストに変換します。」_ （アセットの添付） |
| **既存のリストを編集** | 既存のリストのルールに追加したり、置き換えたりします。 | _「50を超えるリードスコアのルールを&#39;Enterprise Trials&#39; リストに追加します。&quot;_ |

## ユーザーリストの作成 {#create-from-scratch}

生成する前に、次の4つすべてを確認します。 1つのメッセージに欠けている要素を要求します。

1. **ルール/条件** — リストに属するユーザーの平易な言語の説明。
1. **名前** — リストの呼び名。
1. **場所** — リストを配置するプログラム。 プログラム名を指定すると、同僚がそれを見つけます。複数の一致がある場合は、選択を求めます。
1. **Type** – 動的（フィルターベース、自動更新）または静的（固定メンバーシップ）です。 これは必須です。同僚は推測しません。指定しない場合は、次のように尋ねられます。

### 動的リスト {#dynamic-lists}

動的リストの場合、チームメンバーは、ターゲティングを強化するためにパーソナライゼーション属性を含めることを積極的に提案します。 これらの属性はデフォルトで&#x200B;**_含まれています。オプトアウトします。オプトアウトは、_**&#x200B;にはありません。

| 属性 | なぜ役に立つのか |
|---|---|
| **派生ペルソナ** | ペルソナベースのコンテンツターゲティングのためのAIを活用したバイヤーペルソナ。 |
| **派生インテント** | 推測購買意欲シグナルで市場内のアカウントを浮き彫りにする。 |
| **エンゲージメント層** | エンゲージメント済みのコンタクトに優先順位を付ける、計算されたエンゲージメントレベル。 |

作業を開始する前に、これらのいずれかを削除するかどうかを同僚に伝えます。

### 静的リスト {#static-lists}

* **静的、条件なし** - リストは空で作成され、メンバーを手動で追加する準備ができています。
* **条件からの静的（スナップショット）** – 同僚が一致するセットをビルドし、それらのユーザーをコピーします。 母集団は非同期です。Coworkerは、リストが作成されたことを確認しますが、ユーザーが表示されるまでに数分かかる場合があることに注意します。 すぐにリストの準備ができているとは言えません。

## レビューカード {#review-card}

承認するまで何も作成されません。 条件を記述すると、共同作業者はインタラクティブな&#x200B;_人物リスト作成レビュー_ カードを提示します（[!DNL Marketo Engage]件のリストからの適応の場合、カードのタイトルは&#x200B;_人物リスト コンバージョンレビュー_）。

カードの各行は、次の1つの条件を表します。

| 列 | 意味 |
|---|---|
| **要件** （またはアダプテーションの[!DNL Marketo Engage] リスト名） | オリジナルのリクエストまたはソースのMarketo フィルター。 |
| **（ルール）** | その条件に対して生成された実際の属性ベースのルール。 |
| **含める** | そのルールを保存または削除するチェックボックス。 |

**信頼度：**

* **高い信頼性**&#x200B;行は完全に一致し、デフォルトでチェックされます。
* **信頼度が低い**&#x200B;行（おおよそのマッピングまたはフラグ付き）は、通知インジケーターで表示され、デフォルトではオフになっています。
* システムがマップできなかった行は、「**&quot;同等のものが見つかりません&quot;**」と表示しました。これらはルールがなく、チェックを外したままです。

_コンバージョンの概要_&#x200B;では、_N個の高い信頼性_&#x200B;と&#x200B;_N個の低い信頼性_&#x200B;が集計され、ヒントが表示されます。低い信頼性のルールはデフォルトでオフになっています。これらを確認して、チャットに含める変更を記述するか、または確認してください。

**カードアクション：**

* **続行** – チェックしたルールのみを使用してリストを作成します。
* **チャットで必要な変更を説明する** — _で入力を事前入力します「変更したい：&quot;_」を絞り込みます。共同作業者が新しいカードを再生成して表示し、既に承認したルールを維持します。

任意の時点でフォローアップを入力することもできます（例：_&quot;も500人を超える従業員に制限&quot;_）。Coworkerはカードを再生成します。

## 属性マッピング {#attribute-mapping}

条件を記述すると、Coworkerは各条件を実際の既知の人物レベルの属性に変換します。 レビューカードには、次の3つの結果が表示されます。

1. **一致（高い信頼性）** – 条件は属性に直接マッピングされます（例：_&quot;email is acme.com&quot;_ map to the `email` attribute）。 デフォルトでチェックされます。
1. **近似（信頼度が低い）** – 使用可能な最も近い属性が名前またはデータモデルで異なります（例：_リードスコア_&#x200B;として近似されたMarketo _Amount_ フィルター）。 違いを説明するメモが表示されます。デフォルトではオフになっています。
1. **が見つかりません** – 条件を既知の属性にマッピングできませんでした。 _&quot;同等のものが見つかりません&quot;_。ルールは生成されません。

そのため、記述したリストは、指定した条件よりも少ないルールで返される可能性があります。一致しない条件は、サイレントドロップではなく明示的に表示されます。 重要な基準が「見つかりません」の場合は、属性の実名と同僚の再試行を使用して言い換えます。

>[!NOTE]
>
>スプレッドシートの列をフィールド（_Source列_、_ターゲットフィールド_、信頼率、および&#x200B;_マッピングされていない列_ リストを含むフィールドマッピングカード）にマッピングする場合は、オーディエンスの作成ではなく、リードの読み込みフローが使用されます。 [ リードの読み込みスキル ](./skills.md#audiences-people)を参照してください。

## 既存リストのルールの編集 {#edit-rules}

既に持っているリストのルールを変更するように求められると、Coworkerはどのリストと編集モードを確立します。

* **追加/追加** （デフォルト：_&quot;ルールを追加&quot;_, _&quot;さらにルールを追加&quot;_） – 新しいルールが既存のルールと結合されます。
* **置換** （デフォルト：_&quot;ルールを置換&quot;_、_&quot;ルールを&quot;_）は、リスト内の既存のすべてのルールを新しいルールに置き換えます。

チームメンバーは、適用される内容を簡潔に説明し、製品の追加や交換の判断を明確にし、コミットする前に確認を求めます。 適用後、合計ルール数と、追加または置き換えられたルール数がレポートされます。

>[!NOTE]
>
>編集では、結合対応パスを使用するので、「追加」操作によって既存のルールがサイレントに上書きされることはありません。

## オーディエンスの重複 {#overlap}

同僚に2人のユーザーリストを比較するよう依頼します（例：_「第3四半期ウェビナー」と「エンタープライズアカウント」の重複を表示する_）。_人物リストの重複_ カードがレンダリングされます。

* 共通のカウント **&quot;{N}を示すヘッダーバッジ。&quot;**
* 各リストの合計メンバー数と重複が&#x200B;**&quot;X% of A ・ Y% of B.&quot;**&#x200B;の統計行
* 両方のリストの人物のメンバーテーブルで、**名前**&#x200B;列と2番目の列が表示されます。操作できる列は、質問に応じて&#x200B;**電子メール** （デフォルト）、**企業**、**役職**&#x200B;です。
* 任意の名前をクリックして、そのユーザーをワークスペースで開きます。
* 重複がない場合は、カードに次のように明確に表示されます。_「これら2つのリスト間に共通するメンバーはありません。」_

**制限：**

| 制限 | 詳細 |
|---|---|
| **テーブルサイズ** | 最大200人のメンバーを表示します。さらに、メモが&#x200B;_「200人のNを表示しています。検索結果を絞り込むようにクエリを絞り込むように依頼してください。」_ |
| **重複計算** | 電子メールアドレスで計算されます。電子メールを持たないユーザーは積集合から除外されます。 |
| **リストサイズ** | 各リストの最初の約1,000人のメンバーを読み取ります。 大きなリストの場合、Coworkerは結果が部分的であることを示します。 |
| **ドラフト動的リスト** | 比較できません。公開されていないリストにはライブセグメントがありません。 最初に公開するか、代わりに静的リストを使用するようにユーザーに依頼します。 |

## QA検証 {#qa-validation}

リストを作成または更新した後、共同作業者は次を提供します：_「リストが正しく設定されていることを確認しますか？」_ 承認すると、リストが再取得され、次のチェックがレポートされます。

| チェック | 結果 |
|---|---|
| 正しいプログラム/フォルダーの下にリストが見つかりました | 合格/不合格 |
| 適用された内容に一致するフィルター数 | _N_&#x200B;個のフィルター/不一致 |
| 存在するPersonalization属性（含まれる場合） | 存在/存在しない |
| リスト名が要求したものと一致します | 合格/不合格 |
| 推定メンバー数 | _count_&#x200B;またはN/A |

## 制限事項 {#limitations}

| 制限事項 | 詳細 |
|---|---|
| **静的リストの[!DNL Marketo Engage]**&#x200B;からの適応 | [!DNL Marketo Engage]の静的リスト（または電子メールまたはその他のフィルター以外のアセット）を人物リストに適応させることはできません。 静的リストは明示的なメンバーIDであり、フィルターとして表現することはできません。代わりに、スマートリストまたはスマートキャンペーンを要求します。 |
| **アクティビティおよびメンバーシップベースのフィルター** | [!DNL Marketo Engage]から適応する場合、_電子メールが開封された_、_訪問したWeb ページ_、_フォームが入力済み_、_リストのメンバー_、_スマートキャンペーンのメンバー_&#x200B;などのフィルターには、対応する人物リストがなく、「対応するものが見つかりません」と返されます。 |
| **会社レベルの条件** | 可能な限り最も近い人物レベルの属性に翻訳され（人物リストは人物の属性で動作します）、適合性が低い場合に低い信頼性がフラグ付けされます。 |
| **詳細にネストされたAND/OR ロジック** | 複雑なネストされたロジックは、最上位のAND/ORに折りたたまれる可能性があります。Coworkerはこの場合に注意します。 |
| **名前の競合** | 自動的に解決されない – 名前が取得された場合、Coworkerはサフィックスをサイレントに追加するのではなく、別の名前を要求します。 |
| **承認が必要** | 共同作業者は、**[!UICONTROL 続行]**&#x200B;をクリックするか、確認するか、明確な前進を与えるまで、リストを作成または変更しません（_&quot;承認済み&quot;_, _&quot;見栄えが良い&quot;_, _&quot;ビルド&quot;_）。 |
| **静的スナップショット母集団** | 基準から作成された静的リストのメンバーシップは、すぐに入力するのではなく、数分で完了します。 |
